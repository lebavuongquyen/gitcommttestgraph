# R09 - GUI Capability Routing Single Source of Truth

Date: 2026-10-06

## Objective

Close the remaining R08 GUI boundary duplication: the typed capability catalog and the browser controller previously carried the same API route mapping independently.

## Changes

- Added `browserKey` to every `GuiCapabilityDescriptor`.
- Extended the typed GUI capability catalog to contain the browser-facing key and HTTP path together.
- Changed `src/gui/client.ts` to derive `GUI_CAPABILITIES` from `guiCapabilityContracts` at server-side script generation time.
- Removed the duplicated hard-coded browser route map from the GUI client.
- Updated GUI architecture contracts so route ownership is tested through the typed catalog.
- Preserved the existing browser controller API and rendering behavior.

## Architecture Result

The routing chain is now:

`GuiCapabilityId -> GuiCapabilityDescriptor -> browserKey/path -> generated GUI_CAPABILITIES -> capability() -> api()`

A new GUI capability therefore has one typed route definition instead of requiring a second manual browser route declaration.
