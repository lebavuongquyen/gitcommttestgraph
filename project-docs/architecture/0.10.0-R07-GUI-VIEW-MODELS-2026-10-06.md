# R07 — GUI View Models

Date: 2026-10-06

## Objective

Introduce an explicit presentation adapter layer between GUI HTTP payloads and browser renderers without changing existing HTTP contracts or visual behavior.

## Changes

- Added `src/gui/view-models.ts` with pure normalization adapters for:
  - repository status
  - commits
  - graph
  - execution plan and execution state
  - change intelligence
- Added browser-safe `GUI_VIEW_MODEL_SCRIPT` from the same GUI view-model module so the browser controller uses the same normalization contract.
- Updated `src/gui/client.ts` to consume normalized view models before rendering the highest-value panels.
- Kept GUI adapters independent from application, domain, and infrastructure modules.
- Preserved existing API paths, request parameters, response contracts, and GUI behavior.

## Architecture

HTTP response → GUI adapter → GUI view model → renderer

The adapter layer owns transport-shape tolerance and presentation normalization. Renderers should consume the normalized shape rather than depend directly on backend payload details.

## Verification

R07 adds deterministic contract tests for every adapter and verifies that the browser controller consumes the shared view-model script.

Required gates:

- typecheck
- build
- contract suite
- full regression suite

## Acceptance criteria

- Existing GUI API endpoints remain unchanged.
- Status, commit, graph, execution, and change-intelligence panels continue to render from equivalent data.
- Browser controller no longer needs to understand the raw transport shape for these panels.
- View-model code has no application/domain/infrastructure dependency.
- Adapter behavior is deterministic and covered by contract tests.
