# 0.10.2 RCV02 - Backup / Restore

Date: 2026-10-07
Status: IMPLEMENTED

## Goal

Provide a portable, checksum-protected backup and restore mechanism for GCTG-owned repository state without changing Git history.

## State policy

RCV02 includes:

- `.gctg/config.json`
- `.gctg/config-history.jsonl`
- `.gctg/operations.json`
- `.gctg/graph/`
- `.gctg/results/`
- `.gctg/cache/`

RCV02 excludes:

- `.gctg/index.lock`
- `.gctg/manifest.lock`
- temporary `.tmp` and `.tmp-*` artifacts;
- restore staging artifacts.

The policy is embedded in every backup manifest so the contents are explainable and future restore code can reject out-of-policy entries.

## Backup format

A backup is a JSON document with:

- format identifier: `gctg-backup`;
- schema version;
- GCTG version that created the backup;
- creation timestamp;
- explicit inclusion/exclusion policy;
- every file as a relative path;
- byte size;
- SHA-256 checksum;
- base64 encoded file content.

The format is portable and does not contain an absolute repository path.

## Safety

Backup creation is read-only with respect to Git.

Restore performs these stages:

1. Parse and validate the backup manifest.
2. Validate every entry against the supported policy.
3. Recalculate every checksum.
4. Materialize the complete replacement state into a staging directory.
5. Move the current `.gctg` aside.
6. Atomically move the staged state into `.gctg`.
7. Remove the previous state only after the replacement is installed.

If validation fails, the existing GCTG state is not modified.

Git objects, refs, branches and working-tree files outside `.gctg` are never modified by RCV02.

## Surfaces

### GUI

The Recovery section provides:

- Create backup;
- Inspect backup;
- Restore backup;
- visible backup path and result status.

### HTTP

- `GET /api/recovery`
- `POST /api/recovery` with `operation=create|inspect|restore`.

Create defaults to:

`.gctg/backups/gctg-backup-<timestamp>.json`

### MCP

Tool:

- `backup_restore`

Operations:

- `create`
- `inspect`
- `restore`

The MCP surface uses the same application service as HTTP.

## Tests

RCV02 tests cover:

- complete state selection and explicit policy;
- checksum generation and validation;
- successful restore;
- tampered backup rejection;
- preservation of current state when validation fails.
