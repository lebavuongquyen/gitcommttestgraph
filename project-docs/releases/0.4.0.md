# Release 0.4.0

Date: 2026-10-05

## Release goal

Establish the first GUI-first foundation for Git Commit Test Graph without moving business logic into the GUI or MCP adapters.

## Delivered

- Local visual workbench at `gctg serve`.
- Repository and commit explorer.
- Historical commit selection.
- Focused Git → Code → Test impact graph.
- Node inspector with graph evidence.
- Test-impact visibility.
- Query endpoints for future GUI panels: test gaps, execution plan and execution feedback.
- Updated README and changelog.

## Architecture

```
GUI
  ↓
HTTP query boundary
  ↓
Application services
  ↓
Domain graph / impact / test analysis
  ↓
Repository + persistence adapters
```

MCP remains a separate adapter over the same application capabilities.

## Acceptance

- [x] Repository status loads.

## Publish rule

Every future publish must include, before the publish command:

1. Updated `README.md` when public behavior changes.
2. Updated `CHANGELOG.md`.
3. A release note under `docs/releases/`.
4. Tests for new behavior.
5. `npm run check`.
6. `git diff --check`.
7. Clean working tree except generated release artifacts that are intentionally committed.
8. Git commit and push before `npm publish`.
9. Verify the published package version and package contents after publish.

The release process must never publish a version whose documentation does not describe the shipped behavior.
