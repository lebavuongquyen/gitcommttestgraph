# Release 0.8.3

Date: 2026-10-06

## Purpose

0.8.3 is the reliability hardening release for the Unified Change Intelligence foundation.

The release follows the rule:

> Attack the system from its failure boundary, then turn every discovered flaw into a permanent regression test.

## Reliability Work

### Ownership-safe indexing locks

The index lock now uses an ownership UUID.

Release callbacks verify that they still own the lock before removing it. Stale recovery uses an atomic rename to a unique stale path before deletion.

This prevents an old writer from deleting a replacement lock after stale recovery.

### Concurrent graph manifest updates

Graph snapshots were already persisted atomically, but independent writers could race while updating the manifest.

Manifest read-modify-write operations are now serialized through the index lock and the in-memory manifest cache is invalidated before the locked read.

### Git historical failure behavior

Historical reads for missing objects are covered as explicit Git operation failures.

Detached HEAD is treated as having no current branch rather than inventing branch identity.

### GitHub API reliability

GitHub transport failures, HTTP failures and invalid JSON responses now use the typed Git operation error boundary.

Pagination now:

- validates response shape;
- accepts an exact 10,000-record safety boundary when the next page is empty;
- rejects records beyond the safety boundary;
- probes the boundary page explicitly;
- applies the same safety behavior to check runs.

## Permanent Reliability Gate

New command:

npm run reliability:gate

The gate executes:

- build;
- Git reliability tests;
- persistence hardening tests;
- pull-request/GitHub reliability tests;
- incremental indexing tests;
- test-result persistence tests.

Release Gate v2 now executes the reliability gate for versions >= 0.8.3 from a clean checkout.

## No Surface Without Gate

The reliability release does not introduce a new user-facing feature surface. Existing GUI, CLI, HTTP and MCP surfaces inherit the hardened application behavior.

The permanent gate protects the shared application/adapters rather than duplicating reliability logic in each surface.
