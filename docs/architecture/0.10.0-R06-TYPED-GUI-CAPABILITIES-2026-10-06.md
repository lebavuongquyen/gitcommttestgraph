# 0.10.0 R06 — Typed GUI Capability Boundary

Date: 2026-10-06
Baseline: R05

## Objective

Move the GUI from scattered raw HTTP route knowledge toward an explicit typed capability contract without introducing a frontend framework or changing the existing UI behavior.

## Changes

Added `src/gui/contracts.ts` with:

- `GuiCapabilityId`;
- `GuiCapabilityDescriptor`;
- `guiCapabilityContracts`;
- initial GUI view-model contracts for status, commits, graph, execution and change intelligence.

Updated `src/gui/client.ts` so browser API access goes through a centralized capability route map and query builder.

The browser controller no longer calls GUI endpoints through scattered literal `api("/api/…")` expressions.

## Boundary

The intended dependency direction remains:

```
GUI document shell
        ↓
GUI browser controller
        ↓
typed GUI capability contract
        ↓
HTTP capability surface
        ↓
application capabilities
```

The typed contracts contain no application, domain, or infrastructure dependencies.

## Compatibility

No endpoint behavior or GUI workflow was intentionally changed.

The route map is an internal GUI adapter. It translates stable GUI capability identifiers into the existing HTTP paths.

## Contract protection

Added `tests/contracts/0.10.0-gui-capability.contract.test.mjs`.

The contract verifies:

1. Every registered GUI capability has a typed GUI descriptor.
2. The typed descriptor path matches the capability registry.
3. The browser controller centralizes route construction.
4. GUI contracts remain presentation-only.

## Why this matters

R05 separated the GUI shell from the browser controller.

R06 now gives the controller an explicit capability vocabulary. This is the prerequisite for a future view-model adapter that can normalize API payloads before rendering, rather than allowing UI components to depend directly on application response shapes.

## Follow-up

R07 should introduce explicit GUI view-model adapters for the highest-value panels, starting with repository status, change intelligence, graph and execution state.
