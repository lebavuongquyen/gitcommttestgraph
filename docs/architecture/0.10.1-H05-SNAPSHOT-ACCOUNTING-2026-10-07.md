# H05 — Snapshot Accounting and Compaction

Date: 2026-10-07

## Goal

H05 makes snapshot count and size visible and produces a deterministic compaction plan.

It never removes a protected path automatically.

## Accounting

SnapshotAccountingService reports:

- current snapshot count;
- current total size;
- configured maximum count;
- configured maximum size;
- count pressure;
- size pressure.

The values come from the physical GCTG snapshot store.

## Compaction

When limits are exceeded, the planner considers non-protected snapshot records in deterministic path order.

Protected paths are skipped.

The result is a plan only. H04 remains responsible for exact preview/apply execution.

## Safety boundary

H05 does not:

- mutate Git;
- delete snapshots directly;
- invent protection evidence;
- bypass H02/H03 decisions.

## Surfaces

H05 is exposed through:

- HTTP: /api/snapshot-accounting
- HTTP: /api/snapshot-compaction
- MCP: snapshot_accounting
- MCP: snapshot_compaction

## Tests

Tests cover:

- count and size accounting;
- quota pressure;
- protected paths;
- deterministic compaction order.

## Definition of Done

- [x] snapshot count accounting exists;
- [x] snapshot size accounting exists;
- [x] count and size limits are evaluated;
- [x] protected paths are preserved;
- [x] compaction plan is deterministic;
- [x] HTTP and MCP surfaces exist;
- [x] tests and documentation exist.
