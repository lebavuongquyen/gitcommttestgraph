# H03 — Retention Planner

Date: 2026-10-07

## Goal

H03 turns retention policy into a deterministic preview.

It does not delete anything.

For every supplied snapshot candidate, the planner explains why it is protected or why it is eligible.

## Decision order

For each candidate:

1. Retention must be enabled.
2. Existing protection evidence wins.
3. A branch deletion timestamp must be available.
4. The configured deleted-branch grace period must have expired.
5. The result becomes ELIGIBLE only when all required proof exists.

If proof is missing, the candidate remains PROTECTED.

## Quotas

The planner also evaluates configured snapshot count and size limits.

Quota pressure is included as an explanation signal. The planner does not silently delete protected evidence to satisfy a quota.

## Determinism

Candidates are de-duplicated by commit and sorted by timestamp and commit ID.

The caller supplies the evaluation time through the now argument so tests and future maintenance operations can reproduce the same result.

## Surfaces

H03 is exposed through:

- HTTP: POST /api/retention-plan
- MCP: retention_plan

Both surfaces call the same application function.

## Scope boundary

H03 does not:

- physically delete snapshots;
- mutate Git;
- execute cleanup;
- recover interrupted cleanup;
- compact storage.

H04 owns preview/apply execution.

## Tests

Tests cover:

- missing deletion proof;
- grace period enforcement;
- explicit protection;
- deterministic ordering.

## Definition of Done

- [x] deterministic retention planner exists;
- [x] grace period is enforced;
- [x] protected evidence wins;
- [x] missing proof remains protected;
- [x] quota pressure is evaluated;
- [x] HTTP exposure exists;
- [x] MCP exposure exists;
- [x] tests and documentation exist.
