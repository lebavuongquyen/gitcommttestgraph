# O02 — Progress Stages

Date: 2026-10-07

## Goal

O02 makes long-running work observable without exposing internal implementation details.

The runtime records named stages for an operation.

## Current indexing stages

The shared runtime records:

- acquire-lock;
- analyze;
- complete.

The progress model supports both determinate work and unknown totals.

## Mental model

An operation answers:

“What is running?”

Progress answers:

“What stage is it in?”

Diagnostics answer:

“What happened?”

Keeping these concepts separate makes the system easier to understand.

## Surfaces

Progress is available through:

- HTTP: /api/progress?id=<operationId>
- MCP: progress

## Scope boundary

O02 does not implement a UI progress bar yet.

The GUI can consume the existing operation and progress contracts when the GUI operations view is implemented.

O02 also does not attempt distributed progress aggregation.

## Tests

The focused test verifies ordered stages and determinate completion values.

## Definition of Done

- [x] progress stage model exists;
- [x] runtime indexing emits stages;
- [x] determinate and unknown totals are supported;
- [x] HTTP and MCP exposure exists;
- [x] tests and documentation exist.
