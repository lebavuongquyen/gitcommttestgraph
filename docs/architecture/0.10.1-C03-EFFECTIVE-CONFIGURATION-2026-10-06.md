# C03 — Effective Configuration Explanation

## Goal

C03 makes the resolved configuration understandable without asking a developer to inspect several files.

A configuration value can come from three places:

1. **DEFAULT** — the built-in value.
2. **REPOSITORY** — the repository's `.gctg/config.json`.
3. **RUNTIME** — a value supplied for the current process/request.

The precedence is:

`DEFAULT < REPOSITORY < RUNTIME`

When the same setting appears in more than one source, the value from the source on the right wins.

## Simple mental model

Think of configuration as three transparent sheets placed on top of each other:

```text
DEFAULT
   ↓
REPOSITORY
   ↓
RUNTIME
   ↓
EFFECTIVE VALUE
```

The explanation model tells us both the final value and which sheet supplied it.

## What was added

`explainConfiguration(resolved)` produces:

- the precedence order;
- the original configuration sources;
- one entry for each effective leaf value;
- the winning source kind;
- the source location.

Example:

| Setting | Effective value | Source |
|---|---:|---|
| `historyRetention.deletedBranchGracePeriodDays` | 30 | RUNTIME |
| `performance.maxWorkers` | 8 | RUNTIME |
| `cleanup.mode` | conservative | REPOSITORY |

This is deliberately a small explanation model. It does not introduce a second configuration system.

## Why this belongs in 0.10

Configuration migration and safety were added in C01/C02. Without source attribution, a user can still see a final value but cannot easily answer:

> "Why is this value 30?"

C03 closes that usability gap while keeping the existing configuration resolution behavior unchanged.

## Scope boundary

C03 does **not**:

- change precedence rules;
- add a new persistence format;
- add secrets to configuration;
- redesign the GUI;
- introduce a generic rules engine;
- perform a large configuration refactor.

The existing resolver remains responsible for producing the effective configuration. The explanation layer only describes the result.

## Tests

C03 verifies:

- runtime values win over repository values;
- repository values win over defaults;
- unchanged default values remain attributed to DEFAULT;
- source locations are preserved;
- nested configuration paths are represented deterministically.

Current C03 targeted configuration tests: **13/13 PASS**.
