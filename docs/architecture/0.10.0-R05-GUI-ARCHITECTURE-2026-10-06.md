# 0.10.0 R05 — GUI Architecture Foundation

Date: 2026-10-06
Baseline: R04

## Objective

Establish a strict GUI presentation boundary without redesigning the existing UI or breaking its HTTP contract.

R05 separates the server-rendered GUI document shell from the browser controller that performs API orchestration and UI state transitions.

## Boundary

The GUI now has two explicit layers:

- `src/gui/app.ts` — presentation shell: HTML document, CSS, static layout and injection of the browser controller.
- `src/gui/client.ts` — browser controller: API calls, UI state, event handlers and rendering of server-provided capability data.

Neither GUI module imports application, domain, or infrastructure services.

Business capability implementation remains outside the GUI. The GUI consumes the existing HTTP capability surface; it does not instantiate analyzers, stores, Git adapters, runtimes, or persistence services.

## Why this is R05

The previous GUI was already free of TypeScript imports from infrastructure, but its server renderer contained the entire browser controller as one large inline script. That made the presentation shell and UI orchestration boundary implicit.

R05 makes the boundary explicit while preserving behavior.

## Compatibility

No GUI route, DOM identifier, endpoint, or user workflow was intentionally changed.

The browser controller is emitted as the same inline script content as before. The change is structural: the script is now maintained as a dedicated GUI module.

## Contract protection

Added `tests/contracts/0.10.0-gui-architecture.contract.test.mjs`.

The contract verifies:

1. `app.ts` remains a presentation shell.
2. `app.ts` contains no HTTP endpoint knowledge.
3. `app.ts` and `client.ts` contain no direct application/domain/infrastructure imports.
4. Capability orchestration remains in the browser controller.
5. GUI code does not instantiate application analyzers or infrastructure services.

## Architectural direction

The intended dependency direction is now explicit:

```
GUI document shell
        ↓
GUI browser controller
        ↓
HTTP capability surface
        ↓
Application capabilities
        ↓
Domain / ports
        ↓
Infrastructure adapters
```

MCP, CLI and public API remain sibling consumers of application capabilities rather than dependencies of the GUI.
