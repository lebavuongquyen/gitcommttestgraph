# 0.10.2 RCV04 — Interrupted-operation Recovery

Date: 2026-10-07
Status: IMPLEMENTED

## Goal

Make an interrupted GCTG operation explicit, inspectable and recoverable without fabricating state.

## Journal

GCTG persists `.gctg/recovery.json` while an index operation is active. The journal records operation id/name, target commit, recovery phase, timestamps and sanitized metadata. The journal is cleared only after successful completion.

## Recovery

RCV04 provides status, resume and rollback. Resume reruns the deterministic index operation for the recorded Git commit and clears the journal only after success. Rollback clears interrupted recovery state and stale lock artifacts without changing Git history.

## GUI

Recovery includes Resume interrupted and Rollback interrupted. Both require explicit confirmation.

## HTTP

GET `/api/recovery/interrupted` and POST `/api/recovery/interrupted` with `status`, `resume` or `rollback`.

## MCP

Tool `recovery_interrupted` supports `status`, `resume` and `rollback`.

## Tests

Tests cover no-journal status, resume, rollback, journal persistence, HTTP capability and MCP capability.
