# Release 0.7.0

Date: 2026-10-06

## Release goal

Deliver Pull Request Intelligence as a complete feature capability on top of the deterministic Git, semantic graph, test-impact and execution-plan foundation from 0.6.x.

## Delivered

- Added a first-class Pull Request metadata model and review model.
- Added PullRequestChangeSetService for deterministic PR ancestry and commit-level evidence.
- Added a PullRequestProvider application port.
- Added a GitHub REST provider for PR metadata, reviewers, review state, mergeability and check runs.
- Added PullRequestReviewService with deterministic READY, NEEDS_REVIEW, HIGH_RISK, BLOCKED and INCONCLUSIVE decisions.
- Reused semantic graph diff, removed-symbol detection, downstream impact, test gaps, test impact and execution-plan analysis.
- Added MCP tool pull_request_review.
- Added HTTP endpoint /api/pull-request-review.
- Added GUI Pull Request Intelligence cockpit with owner/repository and PR number inputs.
- Added CLI command gctg pr-review <owner/repo> <number>.
- Added unit coverage for PR ChangeSet, review decisions and GitHub metadata mapping.
- Added GUI acceptance coverage for the PR cockpit.
- Hardened npm installation reproducibility by placing TypeScript and Node typings in devDependencies consistently with the build role.
- Added the complete 0.7.0 roadmap and release documentation.

## Decision semantics

- BLOCKED/HIGH for merge conflicts, requested changes or failing/cancelled checks.
- HIGH_RISK/HIGH for removed symbols, high test gaps or impacted projects without runnable commands.
- NEEDS_REVIEW/MEDIUM for drafts, pending checks, unresolved review state, unknown coverage or blocked execution dependencies.
- INCONCLUSIVE/UNKNOWN when no meaningful semantic change can be resolved.
- READY/LOW only when no blocking signal or material uncertainty remains.

## Compatibility

- Existing branch intelligence APIs remain available.
- Pull Request Intelligence is additive.
- MCP and GUI remain adapters over application/domain services.
- Runtime test execution remains behind the existing explicit execution boundary.
- GitHub metadata is provider-based and does not leak GitHub SDK types into the domain.

## Operational requirement

The local repository must contain the PR base/head commits or refs before semantic indexing can analyze them. GitHub PR refs can be fetched locally before invoking PR review.
