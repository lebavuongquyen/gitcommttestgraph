# Release 0.8.2

Date: 2026-10-06

## Purpose

0.8.2 is the performance hardening release for the Unified Change Intelligence foundation.

The release follows:

> Benchmark before optimization.

The performance gate measures the existing behavior, then verifies a concrete optimization against a real Git repository.

## Performance Work

### Batched historical source reads

Before 0.8.2, repository indexing loaded every source file through an individual `git show COMMIT:path` process.

For a 300-file repository this creates hundreds of Git process launches.

0.8.2 adds an optional `readFilesAtCommit` capability to the Git port and implements it in the CLI Git adapter using:

`git cat-file --batch`

Repository indexing uses the batch capability when available and falls back to individual reads for adapters that do not implement it.

### Benchmark classes

The executable performance gate covers:

- 30-file small repository;
- 120-file medium repository;
- 300-file large repository;
- 5/10/20 historical commits;
- cold index;
- warm index;
- repeated historical graph query;
- real Git sequential-vs-batch source reads.

## Measured Evidence

Release environment benchmark:

| Benchmark | Result |
|---|---:|
| Real Git sequential read, 300 files | ~9,917 ms |
| Real Git batch read, 300 files | ~106 ms |
| Batch speedup | ~93.99x |
| Small warm/cold | 9 / 70 ms |
| Medium warm/cold | 10 / 44 ms |
| Large warm/cold | 12 / 63 ms |
| Large repeated 20 queries | 57 ms |

The exact absolute timings are environment-dependent. The important regression contract is that the batch path must remain at least 2x faster than sequential historical reads in the executable gate.
