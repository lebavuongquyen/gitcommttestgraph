# GitCommitTestGraph 0.10.4

## Purpose

0.10.4 is a GUI usability and stability patch for the 0.10 release line. It does not introduce a new architectural boundary or change the MCP capability model.

## User-visible changes

### Graph navigation
The graph canvas now grows with the graph instead of being constrained to a fixed 1000 x 700 viewport. Large graphs can be explored with the canvas horizontal and vertical scrollbars.

Zoom remains available through the **−**, **Reset**, and **+** controls. The graph also shows a short usage hint so a first-time user can understand how to move around it.

### Clearer inspector
The right-hand panel is now presented as **Repository intelligence**. A short explanation tells the user how to read the graph:

**changed code → affected code → tests**

Selecting a node shows a normal summary first. Raw node payload JSON is available only under **Technical details**.

### Cleaner errors
The browser client now reads structured HTTP error responses and extracts the useful message instead of displaying an entire JSON error envelope. Node inspection also handles request failures locally so a single failed request does not create an unhandled browser error.

## Scope

This release keeps the 0.10.x architecture intact:

- GUI remains GUI-first.
- The typed GUI capability catalog remains the routing source of truth.
- HTTP remains the browser/application boundary.
- MCP remains an adapter surface for existing application capabilities.
- No Git history is modified by the GUI.

## Verification

Required release checks:

1. npm run build
2. node --check dist/gui/app.js
3. node --check dist/gui/client.js
4. npm test
5. npm run contract:check
6. Manual GUI verification against E:\10_Learning\Javascript\CV

## Manual acceptance

A release candidate is accepted when:

- The GUI loads without browser syntax errors.
- The graph has usable horizontal and vertical scrolling.
- Zoom changes the graph viewport without losing the graph.
- Selecting a node does not immediately expose a large raw JSON block.
- HTTP failures appear as concise human-readable messages.
- Existing commit selection, test impact, execution, recovery, branch review and PR review controls remain available.
