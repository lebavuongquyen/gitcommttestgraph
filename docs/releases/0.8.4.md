# Release 0.8.4

Date: 2026-10-06

## Purpose

0.8.4 is the Security Hardening release.

The release follows the rule:

> Attack the trust boundary, then turn every discovered weakness into a permanent regression test.

## Security Work

### Git and repository inputs

- Git references reject control characters, whitespace and option-like values.
- Git paths reject absolute paths and traversal components.
- Remote fetch URLs are restricted to the expected GitHub repository URL shape.
- Git operation errors no longer echo the complete command argument vector.
- Sensitive environment variables are removed from child processes by default.

### GitHub metadata

- GitHub owner/repository identifiers use a strict grammar.
- GitHub API endpoint selection is restricted to the official HTTPS API origin.
- Network error messages are sanitized.
- Existing immutable SHA and pagination protections remain in force.

### Configuration

- Configuration paths are explicitly confined to the repository .gctg directory.
- Unknown configuration keys are rejected.
- Existing schema validation remains mandatory.

### HTTP

- JSON request bodies are bounded to 256 KiB.
- Malformed JSON returns HTTP 400.
- Oversized bodies return HTTP 413.
- Internal failures return a stable generic HTTP 500 message.
- Test execution requires an explicit HTTP approval header.

### Process execution

- Child processes do not inherit known credential environment variables by default.
- Structured argument execution remains shell-free.
- The CLI arbitrary run command now requires an explicit --allow-execution flag.

### MCP

- Side-effecting run_execution_plan requires approved=true.
- Read-only MCP analysis remains the default behavior.

## Permanent Security Gate

Command:

npm run security:gate

The gate executes:

- build;
- typecheck;
- security unit tests;
- HTTP security contract tests.

Release Gate v2 must execute the security gate for versions >= 0.8.4.
